# 指令模型的 SSD 与 LAF 实验准备入口

此入口执行指令模型遗忘实验的准备工作：核对历史数据身份和划分，重建共同初始化，重训排除目标训练试次的多任务指令模型，再计算逐试次重要性、原始表征和 VAE。它从历史固定温度模型出发，不增加下游分类头。

运行时传入独立的运行档案目录。初始化需要项目已有的历史指令训练源码、配置、预训练权重和文本缓存；具体文件在生成的阶段配置中登记。运行档案与模型产物分别写入 `.codex/runs/` 和 `artifacts/` 下同名目录。

```bash
python tools/run_instruction_unlearning.py --root /path/to/LEAF-main --run-dir /path/to/LEAF-main/.codex/runs/unique-run-id initialize
python tools/run_instruction_unlearning.py --run-dir /path/to/LEAF-main/.codex/runs/unique-run-id supervise
```

初始化逐项核对17个数据集与历史档案的文件大小、修改时间和样本计数，计算当前文件 SHA256，并保存原始试次索引。训练和验证划分先按历史规则生成，再过滤目标被试的数据。准备阶段的读取入口不解码测试数组，也不读取主目标留出验证试次的标签；文件摘要计算只用于核对文件身份。

监督器依次执行合成数据检查、完整模型与真实梯度检查、100轮排除目标的指令重训、167,091条训练试次的逐试次重要性统计，以及完整分布和前三名目标被试的 VAE 训练。重要性使用固定任务指令、确定性2000点输入、33类交叉熵和 FP32 梯度；同时提取原始表征，并从同一遍扫描累计三个目标被试各48条试次的重要性。

每个实际尝试启动前都会归档包含完整设置、设备 UUID、源码摘要和恢复位置的生效配置。监督器只运行一个 GPU 子进程，允许与服务器已有任务共享 GPU。发生 CUDA OOM 后等待20分钟，再查看所有GPU的可用显存；后续尝试提高显存门槛，保持批次和训练预算。其他错误停止当前队列并保留日志，等待诊断。

指令重训复用历史训练模块的初始化、指令抽样、数据增强、优化器和调度规则，固定第100轮为参照。额外按轮保存完整恢复检查点，OOM后可恢复已完成轮次的优化器、调度和主要随机状态。数据加载工作进程的随机流不能保证跨尝试逐位一致，这一限制需保留在结果解释中。历史完整初始状态没有保存，因此这里只能核对按历史源码和种子重建的初始化，不能声称已经证明与历史起点逐元素相同。

准备队列完成后停在复查点。需要检查掩码覆盖范围、VAE重构误差与固定均值基线、潜变量和输入梯度，再实施计划中的全部即时对照、损失消融、统一评估、后续学习和连续请求。此入口目前不把这些后续部分标为已完成，也不依据测试结果自动搜索参数。

检查运行时读取 `artifacts/<run-id>/runner-state.json`、`retrain-progress.json`、`importance/progress.json` 和运行档案中的阶段日志。完整配置及其SHA256记录在 `manifest.json`；合成检查与模型预检证据保存在 `checks/`。源数据、权重、表征缓存和 VAE 仅保留在实验室服务器的运行产物中，不随源码推送到 GitHub。

## 目标VAE的训练内诊断

准备检查发现目标VAE在原定50轮下可能弱于固定均值重构时，先保存该结果并核对缓存、潜变量和重构偏差。`tools/diagnose_instruction_vae.py` 可在单独的完整配置下执行固定200轮诊断，记录第50、100、200轮的训练表征重构，检查第50轮是否复现原始权重。该入口只读取历史训练表征，诊断权重单独存放；它不自动替换计划中固定50轮的正式产物。正式采用新的VAE训练预算前，需要明确记录协议决定。

## 即时SSD与LAF对照

`tools/run_instruction_laf.py --config <完整阶段配置>` 依次执行真实模型掩码受控检查、直接SSD衰减、全部参数LAF、逐张量等数量随机掩码LAF、重要性掩码LAF、先衰减再LAF，以及两项损失消融。各方法共用固定的40轮配对清单、原模型表征缓存及两份冻结VAE。请求入口读取删除逐试次标签字段后的训练清单，UE与RA分别使用独立Adam，每次更新后投影未选元素并检查缓冲区；三名目标VAE按用户2026年10月25日确认统一采用固定200轮权重，完整分布VAE保持20轮。

程序将七份修改后权重与未做遗忘、排除目标重训两份参照一起生成带SHA256的候选清单。该入口只生成固定候选，统一留出与测试评估在清单固定后另行接续。阶段状态为artifacts运行目录下的immediate/runner-state.json。CUDA OOM使用同样的20分钟等待和全GPU显存重选规则，每次尝试独立归档。CPU公式与梯度检查可用同一入口的--synthetic执行。

## 固定候选后的统一评估

`tools/evaluate_instruction_unlearning.py` 在核对九份候选摘要后，建立17项任务测试与非目标验证、目标48条训练与12条留出、成员推断开发和固定训练表征子集的评估清单。主任务融合指令、默认None文本、任务指令不融合三种视图分别报告，输入固定2000点、FP32、batch32。按当前任务的类别文本计算概率，保留逐试次ID、标签、分数与概率，按项目Metrics定义汇总bAcc、Kappa和补充指标。

正式候选评估前，用原模型48条目标训练试次的重复推理固定数值容差。预测全部完成后计算目标JSD、分类分歧、固定非目标划分的熵成员推断、CKA与共用投影的PCA图；Overall16按数据集等权平均，ADHD单列。九份候选的全部配置、输出与汇总均独立归档，不依结果更换权重或预算。评估和汇总完成后仍须接续计划规定的后续学习与连续请求。

旧即时入口在衰减完成后才开始计时，导致单次SSD时间和组合方法的前置衰减成本缺失。后续入口已将同步计时移到衰减之前，旧候选保留原始记录。评估预检另做一次同步重放，要求全部状态张量与固定SSD候选完全相同，再保存独立成本修正记录；权重不因计时修正而重选。


## 2026-10-25：固定预算的后续学习

新增独立入口tools/continue_instruction_unlearning.py，在全部即时模型固定并评估后，按计划对六份预定模型分别执行两种保留数据条件的200步学习。每种条件独立起步，所有模型共用固定抽样清单，排除目标被试数据，保存0、50、100、200步权重，并记录正常训练模式下的缓冲区变化。采用固定33类交叉熵、FP32和既定AdamW设置；本阶段不根据测试结果选择模型。训练完成后仍需比较同条件、同步数的重训参照，并继续连续三人遗忘请求。已检查语法、抽样数量和数据隔离，OOM保留失败尝试并等待20分钟重新选择单张GPU。


## 2026-10-25：后续学习检查点的同步参照评估

新增独立入口tools/evaluate_continued_unlearning.py，对两种数据条件、六份预定模型的0、50、100、200步检查点分别评估三种固定指令视图。每个检查点与相同数据条件、相同步数的重训模型比较，报告目标训练和留出试次的概率距离、保留任务表现以及固定划分的预测熵成员推断，并生成曲线。训练完成后核对全部48份权重摘要；第0步与既有即时模型的全部状态张量逐元素相等，复用相同协议的预测，避免重复推理。其余36份检查点使用既有已核验预测入口，另存配置、日志和状态；旧产物不覆盖。语法、同步参照存在性和全部权重身份检查通过。全部后续评估及连续请求完成前，不将整项计划标为完成。


## 2026-10-26：连续被试请求与累计排除重训

新增独立连续请求入口，依次撤回三名预定被试。首次请求复用已固定的同方法结果；后两次从上次结果继续，沿用原模型表征缓存和已批准的目标VAE，保留数据累计排除已撤回被试。总体重要性在原模型坐标中按样本数扣除先前目标的贡献，微小负值只作舍入修正。合成加权统计、80批固定配对及累计数据隔离均须通过；每次仍检查掩码外参数、无效模块和全部缓冲区不变。LAF辅助入口新增可配置目标名称，默认仍为S01；旧执行副本保持不变。另存准备入口以支持按排除人数核对训练与验证数量，从保存的共同初始化完成累计排除三人的100轮指令重训；不新增第二次请求的重训参照。源码、配置、权重摘要、独立日志与失败尝试分别归档，OOM等待20分钟再选择单张GPU。该阶段完成后仍需统一评估连续请求效果，不能提前认定完整计划完成。
